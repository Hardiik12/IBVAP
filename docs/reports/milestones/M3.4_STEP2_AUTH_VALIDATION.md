## 1. Authentication Architecture Overview
The IBVAP authentication layer provides end-to-end cryptographic session management:
- **FastAPI Backend:** Handles `POST /api/v1/auth/login`, `GET /api/v1/auth/me`, `POST /api/v1/auth/logout`, and Step 2 TOTP endpoints (`/api/v1/auth/mfa/setup`, `/api/v1/auth/mfa/enable`, `/api/v1/auth/mfa/verify`).
- **Frontend Services:** [`authService.ts`](file:///Users/hardik/Downloads/IBVAP/frontend/services/authService.ts) and [`apiClient.ts`](file:///Users/hardik/Downloads/IBVAP/frontend/services/apiClient.ts) manage token lifecycle and automatic Bearer header injection.
- **Session Context:** [`AuthContext.tsx`](file:///Users/hardik/Downloads/IBVAP/frontend/context/AuthContext.tsx) manages `authState` (`AUTHENTICATED`, `MFA_PENDING`, `UNAUTHENTICATED`, `LOADING`) and exposes `login()`, `verifyMfa()`, `enableMfa()`, `logout()`, `refreshUser()`, and `hasRole()`.
- **Route Guarding:** [`AppShell.tsx`](file:///Users/hardik/Downloads/IBVAP/frontend/components/layout/AppShell.tsx) protects dashboard and tactical surveillance views from unauthenticated access.

## 3. Detailed Component Verification

### A. Login & JWT Flow
1. User enters Operator ID/Email + Password on [`/login`](file:///Users/hardik/Downloads/IBVAP/frontend/app/login/page.tsx).
2. Request dispatched to `POST /api/v1/auth/login`.
3. Backend validates password hash using Argon2id.
4. Token stored in `localStorage` (`ibvap_access_token`).
5. Redirects to `/dashboard` upon successful full authentication.

### B. `/auth/me` Profile & Refresh Persistence
- On browser reload, `AuthProvider` calls `GET /api/v1/auth/me` with Bearer token.
- Returns user metadata: `{ id, username, email, role, mfa_enabled, is_active }`.
- Session survives hard page reloads without requiring re-login.

### C. Protected Route Guarding
- Unauthenticated access to `/dashboard`, `/cameras`, `/events`, `/alerts`, `/evidence`, `/audit-logs` immediately redirects to `/login`.
- Authenticated access to `/login` immediately redirects to `/dashboard`.

### D. RBAC UI Behavior
- `useAuth().hasRole(...)` conditionally renders navigation elements (e.g. Audit Trail is accessible to `ADMINISTRATOR` and `AUDITOR`).
- Role badge displayed in header and sidebar.

### E. Logout & 401 Interception
- `authService.logout()` calls `POST /api/v1/auth/logout`, clears tokens from client storage, and redirects to `/login`.
- Any protected API call returning HTTP 401 triggers immediate token eviction and login redirection.

### F. WebSocket Authentication
- `useWebSocket.ts` attaches `?token=<JWT>` query parameter.
- Backend strictly verifies token signature; rejected with code `1008` if missing or invalid.
