## 1. WebSocket Subsystem Audit Table

| Area | Implementation Details | Status |
|---|---|---|
| **URL Construction** | `ws://localhost:8000/api/v1/ws/events?token=<JWT>` dynamically resolved via window location / env | **PASS** |
| **JWT Acquisition** | Retrieved from `authService.getToken()` (`localStorage`) | **PASS** |
| **Authentication** | Query parameter authentication validated on backend handshake; rejects invalid/missing tokens with code 1008 | **PASS** |
| **Connection State** | Managed reactively in `useWebSocket` (`isWsConnected`, `wsError`), displayed in `SystemStatusBadge` | **PASS** |
| **Reconnect Logic** | Bounded exponential backoff (max 10 attempts, max 10s delay); stops on 1008 Policy Violation / Logout | **PASS** |
| **Heartbeat** | Periodic WebSocket ping frames supported on transport level | **PASS** |
| **Message Parsing** | `mapBackendPayloadToAlert` validates JSON structure and maps `INTRUSION_ALERT` & `EVENT_CREATED` payloads | **PASS** |
| **AlertContext Ingestion** | Global single socket managed in `AlertProvider`, broadcasting to all page views without multi-socket overhead | **PASS** |
| **Duplicate Handling** | Deduplication on both `alert_id` and `event_id` prevents duplicate cards from REST hydration + WebSocket | **PASS** |
| **Cleanup** | Clean `useEffect` cleanup hook cancels timers and terminates socket instance on provider unmount | **PASS** |
| **Error Handling** | Connection errors captured in `connectionError` state; 1008 policy violation triggers session teardown | **PASS** |
| **Token Leakage** | No tokens printed to `console.log` or embedded in UI markup | **PASS** |
