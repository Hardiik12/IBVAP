## 3. Domain Details & Implementation Verification

### A. Cameras & Restricted Zones
- **Endpoints:** `GET /api/v1/cameras` and `GET /api/v1/cameras/{id}/zones`
- **Data Ingestion:**
  - Real camera metadata (`id`, `camera_identifier`, `source_type`, `location`, `status`) is parsed and bound to `CameraContext`.
  - Normalized polygon fence coordinates (`0.0 <= [x, y] <= 1.0`) from PostgreSQL are preserved for dynamic canvas overlay rendering.

### B. Events & Historical Records
- **Endpoint:** `GET /api/v1/events`
- **Features:** Supports query filters (`severity`, `event_type`, `camera_id`, `limit`, `offset`), renders UTC ISO-8601 timestamps, and provides client-side JSON export for evidentiary audit.

### C. Alerts & Operator Acknowledgment
- **Endpoints:** `GET /api/v1/alerts` and `PATCH /api/v1/alerts/{id}`
- **Features:** Initial REST hydration loads active/acknowledged alerts from PostgreSQL; operator acknowledgment sends `PATCH` with JWT Bearer header; RBAC enforces that `AUDITOR` receives 403 upon attempting mutation.

### D. Evidence Vault & SHA-256 Verification
- **Endpoints:** `GET /api/v1/evidence` and `GET /api/v1/evidence/{id}/verify`
- **Features:** Server-authoritative cryptographic verification; UI renders `VERIFIED` (green), `MISMATCH` (red), or `NOT_HASHED` (amber) strictly based on backend computation.

### E. Security Audit Logs
- **Endpoint:** `GET /api/v1/audit-logs`
- **Features:** Accessible only to authorized roles (`ADMINISTRATOR`, `AUDITOR`); displays immutable security events (`LOGIN_SUCCESS`, `ACCOUNT_LOCKED`, `MFA_ENABLED`, `ZONE_CREATED`, `EVIDENCE_ACCESSED`).
